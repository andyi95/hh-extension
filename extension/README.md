# HH Tracker — расширение для Chrome

Отслеживает отклики на hh.ru, синхронизирует их статусы и по клику на иконку показывает карточку текущей вакансии или работодателя: ваш отклик и его историю, ваш отзыв, публичные отзывы других пользователей.

Стек: TypeScript, [WXT](https://wxt.dev) 0.21 (Vite 8, Manifest V3), Preact 11.

## Запуск

Нужны Node.js 24+ и запущенный бэкенд (`../backend`, по умолчанию `http://127.0.0.1:8000`).

```bash
npm install
cp .env.example .env        # адрес бэкенда: WXT_API_URL
npm run dev                 # сборка с автообновлением → .output/chrome-mv3-dev
```

Затем в Chrome откройте `chrome://extensions`, включите «Режим разработчика» и нажмите «Загрузить распакованное» → `.output/chrome-mv3-dev`. Отдельный браузер `npm run dev` не запускает (`webExt.disabled`): сессия hh.ru есть только в вашем основном профиле.

| Команда | Что делает |
|---|---|
| `npm run build` | продакшен-сборка в `.output/chrome-mv3` |
| `npm run zip` | архив для Chrome Web Store |
| `npm run compile` | проверка типов (`tsc --noEmit`) |

`WXT_API_URL` попадает и в код, и в `host_permissions` манифеста, поэтому после смены адреса нужна пересборка.

## Как устроено

```
hh.ru (вкладка)                    service worker                          бэкенд
┌─────────────────┐  sendMessage   ┌───────────────────────────┐  fetch    ┌──────────┐
│ hh.content.ts   │ ─────────────▶ │ background.ts             │ ────────▶ │ FastAPI  │
│ парсинг страниц │ ◀───────────── │ - API-клиент, токены      │           └──────────┘
│ DOM-сигнал      │  tabs.send…    │ - webRequest (отклики)    │
│ синк «Откликов» │                │ - очередь + alarms        │
└─────────────────┘                └───────────────────────────┘
                                             ▲ sendMessage
                                   ┌───────────────────────────┐
                                   │ popup (Preact)            │
                                   └───────────────────────────┘
```

- **Только service worker ходит в бэкенд.** Content script подчиняется CORS страницы hh.ru, а токены не должны попадать в контекст страницы. Popup и content script вызывают в SW типизированные операции (`lib/messages.ts`), а не произвольные запросы. SW проверяет отправителя: операции popup принимаются только со страниц расширения, операции content script — только из вкладок hh.ru.
- **Данные со страниц hh.** Берутся из встроенного JSON `template#HH-Lux-InitialState`, запасной путь — `data-qa` в DOM. Снимок состояния действителен только для URL, с которым страница загрузилась, подробности — в [docs/hh-research.md](docs/hh-research.md). Все селекторы собраны в `lib/hh/selectors.ts`.

### Отслеживание откликов

Три независимых сигнала. Запись в бэкенде идемпотентна: повторный сигнал по той же вакансии только дописывает сопроводительное, если его ещё не было.

1. **webRequest** (`lib/background/tracking.ts`). SW видит `POST /applicant/vacancy_response*`, берёт из тела `vacancy_id` и `letter`, а после ответа 2xx просит content script отдать данные вакансии. `resume_hash` и `_xsrf` не читаются.
2. **DOM** (`entrypoints/hh.content.ts`). Пользователь нажал «Откликнуться» → появился маркер «Резюме доставлено» или снэкбар. Письмо берётся из поля модалки в момент отправки. Маркер засчитывается только после клика на этой странице, чтобы старый отклик не приняли за новый.
3. **Синхронизация «Откликов».** На `/applicant/negotiations` content script отправляет видимую страницу списка в `POST /applications/sync` при загрузке и при клиентской смене страницы. Новые отклики импортируются, статусы обновляются только вперёд: ручной «Оффер» синк не откатит.

Если бэкенд недоступен, события копятся в `storage.local` и досылаются при старте браузера, по будильнику раз в 5 минут и при открытии popup.

### Авторизация

Регистрация необязательна. При установке SW получает токен устройства (`POST /auth/device`), и трекинг работает сразу. Регистрация в popup превращает этого же пользователя в аккаунт. Вход на другом устройстве идёт с токеном этого устройства, и бэкенд переносит его данные в аккаунт. Refresh-токены одноразовые, поэтому обновление выполняется одним запросом на весь SW. Если сессия умерла, SW сразу заводит новое анонимное устройство, чтобы трекинг не останавливался, а popup показывает предупреждение.

### Разрешения

| Разрешение | Зачем |
|---|---|
| `https://hh.ru/*`, `https://*.hh.ru/*` | content script, URL активной вкладки hh.ru в popup, webRequest |
| origin бэкенда | запросы из SW без CORS |
| `storage` | токены, очередь событий |
| `webRequest` | наблюдение (без блокировки) за запросом отклика |
| `scripting` | внедрить content script во вкладку, открытую до установки расширения |
| `alarms` | периодическая досылка очереди |

Разрешения `tabs` нет: URL нужен только для hh.ru и доступен через host permission, так что пользователь не видит предупреждения про историю браузера.

## Не сделано и не проверено

- **Сопроводительное через чат.** Если работодатель уже просмотрел отклик, письмо отправляется только в чат (iframe `chatik.hh.ru/chat/<chat_id>`). Сейчас его можно вставить в карточку вакансии вручную. Доработка: content script на `https://chatik.hh.ru/*` с `all_frames: true`, ловить первое сообщение соискателя, связывать `chat_id` с откликом (в бэкенде добавить `Application.hh_chat_id` / `hh_topic_id`; `chatId` есть в `topicList` «Откликов» и в ответе на отклик).
- **Не проверено на реальном отклике:** письмо, добавленное после отклика (`/applicant/vacancy_response/edit_ajax`), отклик из поисковой выдачи, отклик с тестом, отклик при нескольких резюме.
- **Статусы hh:** встречались только `RESPONSE`, `INTERVIEW`, `DISCARD`. Остальные SW пишет в консоль как неизвестные и пропускает (`lib/hh/statusMap.ts`).
- **Точные даты** для страниц «Откликов» после клиентской пагинации: сейчас берётся относительная дата из DOM. Можно перехватывать XHR страницы в MAIN world.
- **Другие домены hh** (hh.kz, hh.uz, rabota.by и т.д.) не поддержаны.
- **Автотестов нет.**
- **Перед публикацией в Chrome Web Store** проверить название и описание на соответствие политике о товарных знаках (hh.ru упоминается только как сайт, с которым работает расширение).
